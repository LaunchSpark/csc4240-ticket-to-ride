# Using AI Tools to Beat ExampleBot in Ticket to Ride

**Project proposal (revised) — CSC 4240, Artificial Intelligence**

**Team members:** Lucas Starkey, Trigg Lampkins, Trey Gannod, Braylon Trail, Isaiah Chastain

**Terms used in this proposal.**

- **Ticket to Ride** is a board game by Alan R. Moon, published by Days of Wonder in 2004 (https://boardgamegeek.com/boardgame/9209/ticket-to-ride). Players collect colored train cards, spend them to claim routes between cities, and score points for claimed routes and for completing secret destination tickets that name two cities to connect.
- **Our repository** is https://github.com/LaunchSpark/csc4240-ticket-to-ride, a public GitHub repository that holds all code for this project.
- **The engine** is a Python program in that repository that implements the Ticket to Ride rules (`services/native-runtime/src/ticket_to_ride/engine/`). Team member Lucas Starkey wrote it before this course began. It deals and shuffles cards, offers destination tickets, validates and charges route claims, enforces the rule for parallel routes, triggers the final round, and computes final scores. On every turn it gives the acting program the list of moves the rules allow, so an agent can only choose legal moves. It supports the original United States board ("classic map") and the Europe board; Europe's tunnel and train-station rules are not implemented.
- **An agent (or bot)** is a program that plays one seat in a game. It sees only what a human player would: its own cards and tickets, plus public information such as the board, the face-up cards, and opponents' card counts.
- **ExampleBot** (https://github.com/LaunchSpark/csc4240-ticket-to-ride/blob/main/integrations/external/bots/example_bot.py) is a baseline agent in our repository, written deliberately simple but sensible. It keeps the destination tickets that look cheapest to complete, plans the shortest set of routes connecting them, claims a planned route when it can afford one, and otherwise draws the cards that plan still needs.
- **A seed** is a number that fixes the engine's shuffles, so the same seed replays the same deal of cards and tickets.

**Motivation.** Our goal is to build a Ticket to Ride agent that consistently beats ExampleBot. ExampleBot uses every part of the game the engine implements, yet makes no attempt at competitive play: it does not model opponents, block routes, or time the end of the game. Beating it reliably therefore measures real improvements in planning, resource management, and competitive play. We will use available AI tools to find and implement whatever strategy most effectively achieves this goal.

**Description and methodology.** Our repository already contains the engine, seven agents including ExampleBot, interactive marimo notebooks (https://marimo.io) for watching and replaying games, game logs, and scripts for running tournaments and training models. We will use these tools to inspect games lost to ExampleBot, identify weak decisions, and test improvements. Candidate approaches include AI-assisted heuristic design, search and simulation, probabilistic modeling of opponents' hidden cards, and machine learning with existing libraries such as XGBoost (https://xgboost.readthedocs.io). We may combine approaches or abandon them based on results. The objective determines the method; training a model is optional.

We will begin with two-player games on the classic map. Our contribution will be the strategy development, the integration of existing AI tools, and experimental evidence showing which changes help beat ExampleBot. We will document AI assistance and adapted sources, explain our choices, and keep unsuccessful approaches in the experiment record.

**Evaluation.** ExampleBot will be the primary benchmark, with its version fixed throughout each comparison. Our target is a head-to-head win rate above 50% on previously unused evaluation seeds, supported by uncertainty estimates across seed pairs. We will play each seed in both seat orders, to remove any first-player advantage, and control each agent's own randomness separately from the engine's. A pilot will determine the final game count before testing. We will report ties, score margins, ticket completion, and decision time alongside wins. Development and final evaluation seeds will remain separate; any learned models will also use separate training and validation games. Removing individual strategy components one at a time will show which changes improve performance. Other agents can provide secondary comparisons, but success is measured against ExampleBot.
